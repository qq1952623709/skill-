# 制作与衔接规范

## 最小工程记录

项目放在用户指定目录或当前工作区下 `动画项目/<唯一项目名>/`。保存 `brief.md` 原话与假设、`production.json` 状态、`story.md` 剧本台词、`shots.json` 镜头计划，以及必要参考图、声音、视频和审片记录。远程资产保留真实工程/资产链接，不为凑文件数量生成占位成片。

`production.json` 至少记录：

- `projectId`、`status`、`resumeStage`、`updatedAt`、`sourceRequest`；
- `spec`：目标时长、容差、画幅、帧率、输出分辨率、语言、画风、硬标准、禁改项；
- `authorization`：预算币种、上限、已有授权依据、普通创意委托范围、是否允许外传给指定审核方；
- `budget`：已消耗、在途预留、下一步预估、剩余全片预估、返工预留、费用来源和查询时间；未知金额用 null，不能填0，也不能当可支付；
- `characters`、`locations`、`props`：稳定 ID、固定特征、参考资产及其版本；
- `shots`：镜头 ID、节拍和台词 ID、参考版本、生产状态、生成任务与费用、被采用素材；
- `timeline`：真实工程及时间线 ID、帧率、各素材的入点出点与位置、已落位 itemId 与镜头映射；
- `review`：制作方、审核方实际身份、审查范围、未检项、结论、证据、候选版本/哈希；独立于导出状态；
- `export`：renderId、状态、结果路径/URL、实测时长与规格。

每次付费提交先保存最高扣费预留；成功按真实扣费结算，超时仍保留预留，退款或未扣费有证据后才释放。小样通过后尽量直接用于正片，避免重复生成。同样记录方向/成品审查可能发生的费用。每次小样结束重新评估全片剩余费用。

异步恢复：查原 jobId，运行中继续等待；成功后核验 outputAssetId，并查询时间线是否已有对应 itemId，再决定是否入轨；失败后核实扣费和预算才重试。导出查原 renderId，成功就复用该版本，避免重复导出。若使用续接自动化，保存其真实 ID，完成或取消任务时关闭本项目续接，避免重复执行。

## 分镜和提示词统一底稿

每个镜头包含：`id / beatIds / characterIds / locationId / propStates / durationSeconds / framing / camera / action / startState / endState / dialogueIds / sound / referenceAssets / imagePrompt / motionBrief / providerPrompt`。

将故事句子变成摄影指令时，补齐主体、动作、场景、空间位置、景别、运镜、光色、动画材质和声音。每镜一个主要视觉意图，避免把多个互相矛盾的运镜堆在一起。视觉描述用可见行为表达情绪；人物内心通过表演、对白或叙事表达。

`motionBrief` 保持模型无关；`providerPrompt` 才按当前模型语法编译。H3 的台词块、参考索引和切点格式按其文档；其他模型另编译。保持台词逐字一致，所有引用对应真实素材，不能凭空写“参考图1”。

相邻镜头登记视线、行进方向、手持道具、服装、光线和动作状态。转场分为普通剪切、声画错位、叠化或生成桥接；用叙事选择，不默认每镜加特效。人物进入画面的位置与下一镜保持空间逻辑。

## 动作片投产硬门

打斗、追击、武器战、强碰撞或动作预演必须完整执行 [动作与打击感规范](combat-impact.md)。在逐招动作表、多武器逐镜状态表、重心受力表、空间路线图、镜头节奏表、声音 cue 表和低成本动态预演齐全前，禁止提交付费长片生成。先做 6—8 秒代表段；`PILOT_PASS` 必须同时满足角色可辨、多武器与握点无矛盾、攻击—接触—受力—反应—后果静音可读、空间连续、声音层级可分，并由用户观看真实可播放版本后决定。执行者不得自批通过。

## 声音先后顺序

- 对白驱动：先锁台词，生成/复用角色声音并测量时长，再安排镜头和口型；或者使用支持原生对白的模型同时生成音画，实际检查文字、角色归属和嘴型。
- 动作驱动：先生成动作镜头，保留有效原生环境音，再放旁白、音效和音乐。
- 音乐驱动：先确定可用音乐与节拍，再剪动作和镜头；已有用户音轨优先。

台词底稿每句有 ID、说话人、原文、语气和所在节拍。配音完成后记录音色 ID、实际时长和素材 ID；不要只凭每秒字数断言装得下。时间不足先改停顿或镜头长度；台词可修改时才压缩文字，不把配音加速到失真。对白与旁白分轨；去掉重复叠加的原生对白，背景音乐在说话时降低。

TTS 仅合成语音，不自动解决口型。无口型工具时可以在不违背用户硬标准的前提下选择背影、反应镜头或画外对白；必须正面开口且无可用能力时明确记能力缺口。每个角色的声音在全片保持一致，不能逐句重新选音色。

## 剪辑与检查

以实际时间线帧率将秒转换成帧；动作段按需要保留衔接余量，合成后测量实际总时长，不把各次生成时长简单相加当最终时长。

字幕从最终采用的语音和锁定台词对齐，检查漏字、错字、换行、显示时间和画幅安全区。用当前文字工具生成字幕，避免让图像/视频模型直接烘焙长段中文。输出片尾保留必要余量，避免台词、动作或音乐突然切断。

检查应包含：

1. 内容：用户要求是否兑现，故事是否能看懂，台词和字幕是否对应。
2. 动画：角色身份、服装、比例、关键道具状态、画风、动作与空间连续性，是否有静帧冒充动作。
3. 声音：实际试听全片；对白清楚、角色正确、无重音和截断，要求的口型对齐可见。
4. 剪辑：合成预览每个剪切两侧、代表动作段和首尾；单张关键帧不能证明整段动作成功。
5. 技术：实际时长、画幅、分辨率、音视频流、可播放性；字幕无遮挡。

## 审核合同

生产前固定审查标准。独立方向审查读取原话、目标、备选路线、事实和预算；独立成品审查读取同一套标准、故事、镜头计划和真实候选成片，不带制作方“已通过”的诱导结论。审核方只报告、不改片，记录实际模型/会话及文件哈希。用户点名 Grok 就优先找真实 Grok 入口，不能把同模型子代理称作 Grok 或另一产品线。

可用独立代理进行内部规则审查或初筛，但须按 总经理的当前审计协议判定是否满足最终审计要求。审核方看不到视频或听不到音频时，将相应维度标为未检，不能用文字摘要代替成片审核。若需要外传，核对用户已有范围授权，只发送本片所需材料。

审核结果给出 PASS / REWORK / UNREVIEWED，问题附时间码、硬标准、严重程度、建议和证据。只重做受影响的镜头和下游；改动导致旧哈希失效，重新审核。审核通过的是特定导出版本；如再次重新编码或导出，至少复核音画和字幕与已审候选一致。

例如文件已导出但审查方不能听音频：保留 export.status=SUCCEEDED、原 renderId 和哈希；review.status=UNREVIEWED，unreviewedDimensions 包含 audio。寻找满足协议且能试听同版音轨的审查方补审。可以明确标记待审预览，但不得宣布最终完成。

## 回归案例（离线推演，不花生成额度）

- “雨夜小狐狸把伞借给小机器人，60秒温暖动画，工具和配音你定，预算20美元”：应自动补剧情、固定两角色和雨景、区分对白与雨声、选择小样并预算预留；不把普通参数逐个交给用户。
- 同一请求没预算：完成剧本和分镜规划，付费调用前只补金额；不得把 null 当免费或已有无限额度。
- “必须中文正面对白、用MiniMax”：走实际 H3/指定模型入口，核口型和逐字台词，不静默换模型或改旁白。
- “上一段超时了，继续”：先查已存任务，再决定是否重试，不能重复扣费。
- “改主角衣服”：更新角色参考版本并定位所有受影响镜头，不只改一张设定图；旧审计失效。
- “视频导出成功，但审查者只读到脚本”：可交付标明待审的预览，不能标最终审查通过。
