# 动作与打击感规范

适用：打斗、追击、武器战、动作片、强碰撞、动作预演，以及用户要求“打得狠、快、爽、有压迫感”。这是投产规范，不是形容词库。

## 证据边界

本规范来自用户提供的 `拆解报告.md` 与 `打开看拆解.html`。可直接观察到的是 35 个连续分析单元、时间码图版、音频包络与报告中的动作/空间/注意力结构；尚未证实的是原帧零遗漏镜表、原始帧率和剪辑管线、可靠直接听审、作者实际工具成本，以及任一生成模型已经成功复刻。未做真实代表段前，能力等级只能写 `PACKAGED_PENDING_END_TO_END_PRODUCTION_TEST`，不得宣称“已掌握工业级打斗”。

需要设计逐镜动作、复查参考片节奏或定位某段机制时，继续完整读取 [35 个连续分析单元证据映射](combat-reference-35-units.md)。该表保留每段时间码、观察、机制和制作标准，不能只凭本页总则替代逐段回查。

## 一、打击感的六段因果链

每个有效打击都必须回答六个问题：

1. **攻击成立**：谁出招、哪一侧肢体、武器从哪到哪、目标是什么。
2. **接触成立**：武器、身体或环境的交点清楚；火花不能代替接触。
3. **受力成立**：支撑脚、膝胯、肩轴、握点与武器线路共同传力，不能只有手臂摆动。
4. **反应成立**：对手必须闪避、格挡、卸力、滑退、失衡或反击；双方动作互为因果。
5. **后果成立**：位置、地面、建筑、道具或危险级别发生变化；动作必须改变世界。
6. **声画成立**：挥空、接触、抵刃、滑退、落地、破坏和终击使用不同声音层，并对准同一事件。

一句话检查：谁攻击，危险多近，哪里接触，力量怎样穿过身体，结果改变了什么，声音是否为同一件事作证。

## 二、三条结构同时推进

### 动作线

追逐 → 试探 → 连招 → 险招 → 脱险 → 终击。不要从头到尾重复同一种砍法；每一段必须提出新的攻防问题。

### 空间线

开阔处认路 → 屋顶拉距 → 窄台受限 → 楼体外或移动载体改变规则。换场必须有动作因果，例如被剑气逼退、撞破墙体、跃迁追击；不能只是突然换背景。

### 注意力线

远景交代地理和距离；双人全身景读攻防；近景看危险和受力；极近景只给握点、刃尖、眼神等关键事实；抽象图形或强特效只给稀缺重音。全片都按终结技处理会失去层级。

## 三、快、慢、抽帧与镜头

爽感来自密度变化，不来自统一倍速：

- 接近、追击、回击快；第一次擦身、刃尖近眼、持续抵刃、失衡和终击姿态必须让观众读懂。
- 快段使用短动作间隔和明确切点；慢段只服务危险、重量、蓄力或结果，不用于普通跳跃与漂浮。
- 瞬移要有“离开—路径或残影—到达—冲击”的视觉证据，不能删掉中间因果后突然开打。
- 抽帧、速度坡度、动感模糊、镜头震动只强化已经成立的动作；不得用来遮掩少刀、换手、肢体变形、空间跳接或无接触。
- 重击可在接触前极短停顿，接触帧明确，接触后迅速兑现反应和环境后果。镜头震动方向应服从受力方向。
- 生成段时长、剪辑镜头时长和动作节拍是三件事，禁止把“每镜 2—5 秒”机械套进高密度打斗。

## 四、逐招动作表：没有这张表不得生成

每一拍至少写：

`beatId / attackCharacter / attackLimb / weaponId / startGrip / attackPath / target / defenseCharacter / defenseLimb / defenseWeaponId / contactPoint / supportFoot / centerOfGravity / forceDirection / reaction / environmentConsequence / startState / endState / camera / cutPoint / soundCue`

写法必须具体到：左手还是右手、嘴部是否咬刀柄、哪只脚承重、肩胯如何转、哪把刀先挡、哪把刀后反击。禁止只写“三刀齐出”“疯狂对打”“电影级打击感”。

## 五、多武器和角色连续性

- 为每个角色建立固定武器库存、长度、握点、持有部位和逐镜起止状态。
- 每镜分别登记每件武器：攻击、格挡、回收、架刀、保持或离手；不能把总数交给模型猜。
- 已知回归案例：奶龙三刀设定必须始终是嘴咬一把刀柄、左手一把、右手一把。任何一镜少刀、换手、刀长突变、咬住刀刃或嘴刀消失，直接判连续性失败。
- 豆包月下蓄力的冻结动作是左手持刀、右手缓慢拂过刀身；若项目另有手性设定，先冻结后全片一致。
- 若双方是死敌，禁止背靠背、并肩停留、亲密接触或队友式协同。每次靠近都必须由攻击、压迫、闪避、格挡或反击造成。

## 六、重心与力量

- 出招前写支撑脚与蓄力方向；接触时写肩胯旋转、膝部弯曲与重心高度；接触后写滑退、回弹、失衡或恢复。
- 强攻击不能让攻方上身前冲、下身完全不动；重格挡不能让守方像静态支架。
- 跳跃要服从重力：起跳压缩、腾空路径、落地冲击、膝胯吸收、重新站稳。普通跳跃不得无理由慢飘。
- 无特效、无声音时若仍看不懂攻防和受力，动作本身不合格。

## 七、空间路线和破坏升级

投产前画位置图并编号入口、出口、高低差、障碍、可破坏物和双方朝向。每次切换地点写清触发动作与到达状态。

破坏按层级升级：局部碎地/玻璃 → 切开楼体并改变追击路线 → 大招影响整片楼群。切楼等重大后果先给短远景，让观众确认空间真的改变，再切回追击。特效应证明力量，不替代力量。

## 八、声音设计

- 挥空、金属接触、持续抵刃、脚步、滑退、落地、钢结构撕裂、电弧、爆炸和角色发力分层制作。
- 音乐负责跨镜头推进，不要求每一刀卡鼓点；关键接触、换场和重击与节奏重音建立关系。
- 关键重击可先短暂抽空或压低背景，再进入瞬态冲击和低频尾音；不能每刀都用相同“咚”。
- 环境声跨剪辑保持连续，同时随屋顶、街道、室内、车顶等空间改变反射与风噪。
- 最终三遍审片：只听声音、静音看画面、声画合看。

当前来源只证明混合音轨信号测量，不足以确定具体歌曲、BPM、音色与逐击卡点，这些保持 `UNKNOWN` 并在真实项目里试听确定。

## 九、强制中间件

付费长片前必须齐备：

1. 角色多视图与极端动作轮廓；
2. 武器连续性表；
3. 逐招动作表；
4. 重心受力表；
5. 空间路线图；
6. 镜头节奏表；
7. 声音 cue 表；
8. 低成本动态预演；
9. 代表段验收表。

静态关键帧、文字稿、长提示词、任务已提交或文件已导出，都不能冒充动态预演或动作通过。

## 十、6—8 秒代表段与 PILOT_PASS

先验证最容易暴露问题的一段：拉开距离 → 突进横扫 → 近脸闪避 → 左右手分别格挡/反击 → 抵刃受压 → 脚步滑退 → 分开回位。

通过条件：

- 两个角色始终可辨；
- 逐招与冻结动作表一致；
- 多武器数量、长度、左右手及嘴部握点逐镜可解释；
- 攻击、接触、受力、反应、后果在静音画面中成立；
- 没有漂浮落地、死敌背靠背、空间跳接；
- 快慢有层级，瞬移因果可见；
- 加入声音后挥空、格挡、抵刃和重击可区分；
- 逐帧/逐拍检查无硬伤；最终由用户观看真实可播放版本决定 PASS，制作方不得自批。

代表段失败时先改动作资产、动作拆法、空间路线或模型路线；禁止只叠加“更燃、更电影级”等形容词继续扣费。只有 `PILOT_PASS` 后才可扩展到切楼、分身、法阵、巨龙、银河对轰等高成本场面。

## 十一、生产接力

`ai-master` 冻结目标、预算和方向；`novel-characters` 做角色多视图与动作轮廓；`novel-art` 做空间与道具锚点；`novel-script` 拆稳定动作节拍；`novel-storyboard` 认领节拍、镜头、切点和批次；`maomao-animation-studio` 统筹动态预演、代表段、声音、剪辑与状态；视频模型只在上游通过后执行；验证工具必须查看真实可播放版本。

## 十二、动作控制硬门（GitHub 吸收版）

这部分吸收了公开项目的可验证方法，但不把仓库存在、README 或论文结果当成本机能力证明。相关依据：Tencent/MimicMotion 的置信度姿态引导、AnimateDiff 的 ControlNet/SparseCtrl 条件控制、以及 Kimodo practical 的根运动、末端约束、IK、角色 rig 认证和 QA gate。

### 12.1 纯文字直生成禁令

- 动作片代表段不得只提交“角色参考图 + 长提示词”。必须同时存在一种可检查的动作控制载体：3D/骨骼预演、逐帧姿态序列、可播放的动作参考视频，或等价的关键帧与根运动数据。
- ChatCut/视频模型若只能接图片和文字，最多用于风格或角色外观探针；不能把它的结果称为“动作控制通过”，也不能直接扩成整片。
- 对非人形角色（奶龙、龙、机械兽等），人体姿态模型只能作为动作代理；必须增加角色自己的 rig/IK 或明确的代理到角色映射，不能假设人体骨骼会自动保留爪、尾、嘴咬武器和重心。

### 12.2 动作控制数据契约

每个代表段在生成前必须保存机器可读的 `motion_control.json`，至少包含：

`frameRate / durationFrames / actorId / rootPath / supportFootByFrame / centerOfMassByFrame / pelvisRotationByFrame / contactEvents / endEffectorTargets / weaponStateByFrame / cameraPath`。

其中：

- `rootPath` 必须能解释前进、后退、滑退、旋身和落地，不得用镜头推拉冒充角色位移；
- `supportFootByFrame` 必须标出承重脚、换重心和离地区间；
- `centerOfMassByFrame` 必须在攻击、接触、受击和恢复四个阶段有可见变化；
- `contactEvents` 必须有 `attacker / target / contactPoint / contactFrame / forceDirection / reactionWindow`；
- `endEffectorTargets` 至少覆盖手、脚和武器接触点；
- `weaponStateByFrame` 必须能逐帧解释每把武器的位置、握点和持有部位。

缺任一字段，状态只能是 `MOTION_PLAN_INCOMPLETE`，禁止付费角色生成。

### 12.3 角色套入前的验证顺序

必须按“先动作、后角色、再风格”的顺序执行：

1. **代理预演**：用白模/骨架/低模验证双方距离、攻击线路、接触和位移；白模不是会动就算通过，必须能静音看懂因果。
2. **控制一致性检查**：检查关键帧、根运动、支撑脚、重心、手脚目标和接触事件；若工具支持约束误差，记录误差，不得只凭肉眼说“差不多”。
3. **角色套入**：把动作映射到已锁定角色 rig；非人形角色要单独检查嘴咬武器、尾部/翅膀、爪和衣物惯性。
4. **风格化生成**：最后才用视频模型或渲染器完成材质、光照、镜头和音效。风格化结果不能覆盖动作控制失败。

### 12.4 受力与慢动作硬验收

- 慢动作只允许放在“攻击即将命中、主动闪避、接触停顿、受击变形或重心恢复”上；若攻击者没有继续穿过目标线、受击者没有主动位移或卸力，慢动作判定为 `SLOW_MOTION_WITHOUT_EVENT`，直接返工。
- 每个重击至少要出现：蓄力压缩 → 支撑脚蹬地 → 接触/擦过 → 重心穿透或被打断 → 位移/滑退/回弹 → 重新站稳。缺一环不得用音效、镜头震动或闪光补救。
- 踢击、撞击和斩击必须标注位移容差；默认要求受击者根位置在接触后发生可见变化，除非动作表明确写“卸力不退”。
- “砍空气后收回”“双方同时摆姿势”“只用镜头推进制造冲击”均为硬失败案例，进入永久回归集。

### 12.5 工具路由与证据标签

- 姿态引导类（如 MimicMotion、AnimateDiff+ControlNet）适合把已存在的动作序列迁移到外观/风格；不能替代双人接触设计，也不能保证三把武器连续。
- 约束/骨骼类（如 Kimodo practical 所示的 canonical skeleton、root waypoints、end-effector targets、IK 和 rig certification）优先用于需要重心、脚步、击退和武器接触的动作。
- 工具未实际安装、未在本机跑出代表段、或只看过仓库说明时，能力登记为 `REFERENCE_ONLY`；只有真实输入、输出、日志和审片证据齐全，才可登记 `RUNTIME_VERIFIED`。
- 每次动作探针报告必须分栏：`motion_control_status`、`character_consistency_status`、`audio_status`、`host_tool_status`。任何一栏未测写 `UNKNOWN`，不得用角色图通过冒充动作通过。

## 十三、禁止付费的情况

缺逐招表、武器表、重心表、空间路线、动态预演、代表段用户 PASS、真实扣费上限或剩余全片预算任一项，禁止下一次付费生成。若审查者看不到动态画面或听不到声音，该维度只能标未检，不能全面 PASS。
