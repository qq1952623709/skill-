# 茂茂动画工厂

茂茂是 CEO，当前 Codex 是导演兼制片总经理。用户描述想要的故事、场面或情绪，总经理补齐专业制作细节并调用工具，交付可播放动画和可继续修改的工程。默认目标约一分钟，用户指定优先。

这是可由 Codex 执行的组合技能，不内置视频模型、付费额度或云渲染服务。“一键”表示一次自然语言任务驱动全流程；不能把写好文档、工具可见、任务已提交说成成片已完成。

## 输入与自主权

- 先保存用户原话，区分必须保留的内容和自己补充的创作。已给过的预算、平台、音色、风格和审核要求沿用，不重复询问。
- 常规创意由总经理决定：默认单集约60秒、中文对白，画幅根据发布用途判断，无用途时用16:9并记录假设；动画风格由故事决定，选一套色彩、造型和材质贯穿全片。不得把“动画”悄悄做成静态图片幻灯片。
- 用户已委托全流程时，普通镜头、官方音色、分段方式、提示词与局部返工由总经理决定。子技能里为普通用户设置的逐步选项和重复确认，按当前用户的明确委托处理；不替用户同意付费升级、超支或声音克隆。
- 用户的故事、结局、台词原文、参考角色、点名模型和硬标准优先。专业补充不得悄悄改变核心意图；有实质冲突先说明证据和建议。
- 没有预算上限时先完成免费文本规划和成本方案，在首次消耗付费额度前集中确认金额。预算内已有授权无需逐镜批准。制作授权包含任务必要的素材生成、项目编辑和出片，不包含对外发布。

## 主路线

当前优先使用 Codex 创作统筹 + 现有 novel 系列的方法 + ChatCut 执行工程。模型选择以当前工具能力和小样表现为依据；用户点名 MiniMax 时在可用接口中优先使用，不让用户在“平台或模型”之间反复选择。

### 语义启动路由（硬制约）

读取 `references/task-router.json`。不能因为用户没有说“分镜”“四视图”“角色设定”就跳过对应技能：只要最终目标是多镜头动画，或描述中出现打斗、追击、武器、踢击、碰撞、重心、打击感，必须走 `animation_combat_oneshot` 或 `animation_dialogue_oneshot` 路由，并记录每个 `must_load` 技能的读取路径、哈希和运行状态。关键词只是加速，不是唯一触发条件。

先按规模选生产模式，避免把短镜头误送进长片流水线：

- `FAST_SHOT`：单段且不超过15秒，用户已给清楚的角色、场景和动作。只做一页以内的导演包，直接编译模型提示词；除非有重复角色、跨段连续性或用户点名，不加载完整 novel 五件套。
- `SHORT_FILM`：16–60秒、多段或有明确剧情弧。使用剧本、角色、场景和分镜，但材料深度按难点缩放。
- `WORLD_FIRST`：系列、反复复用场景、复杂空间调度、游戏 CG 或长连续性任务。先搭空间真相层和可复用资产，再逐镜生成。

`FAST_SHOT` 的紧凑导演包必须写清：观众感受、角色与站位、动作因果、摄影机、时间节拍、连续性锚点、对白/声景、禁止项。它是导演判断，不是额外让用户填表。短任务满足这些字段后，不得仅为凑流程扩写长剧本、角色百科或多份重复文档。

对重复角色，`novel-characters` 的角色卡/设定图（三视图或四视图，按工具实际产出）是默认一致性锚点；缺失时必须生成，或记录明确的 `N/A` 理由，不能直接把文字提示词当成定妆照。多镜头任务必须有 `novel-storyboard` 的节拍、时长、机位和运镜底稿；没有底稿不得提交生成。自建视频生成适配器必须消费 `scripts/startup_adapter.py` 的回执并通过 `scripts/generation_gate.py`；路由只列技能、不读技能、不产生回执，视为启动失败。宿主原生 ChatCut/MCP/浏览器入口是否能被拦截必须单独实测，未测只能写 `HOST_NATIVE_ENTRYPOINTS=UNKNOWN`。

### 生产前硬门（不得跳过）

#### 从外部调研吸收的硬性要求

外部 Demo、帖子和 GitHub README 只能作为 `SOURCE/REFERENCE`，不能直接当成我司能力。动画工厂必须把生产拆成可回退的对象：角色、场景、道具、剧本、节拍、镜头、关键帧、视频片段、声轨和时间线。每个对象都要有稳定 ID、版本和验收状态，避免“整片一次生成”后无法定位失败。

- 先做前期资产和关键帧，再做镜头视频；角色连续性不靠重复提示词。
- 对动作任务把“发力者、受力者、接触点、重心、位移、恢复、声音节拍”写成结构化字段；只写“打得很有力量”不合格。
- 对对白任务把“角色意图、潜台词、停顿、重音、音色、口型输入”写入台词底稿；原生音频和一体化 Demo 仍须单独验收。
- 对剪辑任务优先选择可脚本化、可复现、可回滚的时间线或 JSON 工程；纯 GUI 点击若无回执只能记 `UNKNOWN`。
- 外部工具的“端到端”主张必须拆成五个探针：资产一致性、镜头动作、声线/口型、时间线/导出、成本与恢复。

1. **来源与制作方式门**：对参考视频先做文件元数据、来源链接/原帖、可见水印与制作记录核验。只能证明容器/编码时，制作平台和模型必须标为 `UNKNOWN`，禁止凭画面风格猜“这是某平台做的”。
2. **工具适配门**：逐项核对本机可执行工具、登录态、模型/依赖、操作系统兼容性和实际调用入口。技能文件、GitHub 源码或浏览器按钮存在，不等于工具可运行；缺工具时总经理先检索、审安全、安装并做最小真实探针，只有需要付费、登录、系统权限或许可注册才停下来找 CEO。
3. **难点代表段门**：涉及双人打斗、碰撞、闪避、重心、武器或复杂口型时，先用实际目标路线做 2–8 秒最小代表段，至少验证“攻击—接触—受力/闪避—后果—声音”因果链；未通过前冻结付费长片。
4. **能力与成本证据门**：提交前必须记录平台、模型、任务 ID、预计扣费、剩余额度和回滚/返工预算。只看到“已提交”不能写成“已验证会做”；费用或扣费上限未知时不提交。

开始操作前读 [制作与衔接规范](references/production.md)。需要模型选择、子技能定位或能力预检时读 [工具路由](references/routing.md)。理解吸收了哪些优点和限制时读 [融合依据](references/fusion.md)。凡用户提到打斗、追击、武器战、动作片、打击感、碰撞感、动作预演或要求“打得狠/快/爽”，必须在规划与任何生产动作前完整读取 [动作与打击感规范](references/combat-impact.md)，不能只凭长提示词直接提交生成。

1. **编译创意**：把原话写成简短故事、观众应感受到什么、开场信息、变化和结尾。默认用适合一分钟的紧凑故事，不机械强加连载爽点或结尾悬念。固定硬标准和预算。收费生产前按 总经理要求交独立模型审方向。
2. **剧本与声音底稿**：写带稳定编号的动作节拍与逐句对白，明确说话人、语气、停顿、旁白和声景。按估计语速规划，但实测配音时长才是剪辑依据。用户要求动画片且没有明确要求默片时，导演应主动判断是否需要对白、旁白、环境声、动作音效和配乐；有台词的任务不得把声音遗漏后作为成片交付。
3. **美术资产**：给重复出现的角色固定面部、体型、服装、动作特征及音色；场景固定空间、光照和可识别细节，道具登记尺寸和状态。生成并检查必要参考图，记录真实资产 ID。
4. **分镜与动态预演**：把节拍映射到镜头，设计景别、机位、运镜、动作、视线和转场。先制作关键帧与低成本预演判断节奏；预演标成草稿。根据实际模型时长限制决定生成段落，段落可以含多个镜头。
5. **动画生产**：先生成一个最能暴露难点的代表段，检查角色、动作、声音、口型和剪辑衔接。在授权预算内通过后继续；每段复用参考资产，不只重复文字。留存任务 ID 和失败原因，按实际异步机制续接。
6. **声音与剪辑**：对白优先清楚、角色声音保持一致。先为每个主要角色确定一条声音导演说明，再用1–2句代表台词试听；检查音色是否贴角色、情绪是否自然、语速是否机械、重音停顿是否正确，通过后才批量合成。原生对白可用时保留；另配 TTS 时使用可用的情绪、表演、语速和局部提示控制并验证口型，不把“音频已贴上”当成“嘴型已对齐”。完成画面剪辑、声音对齐、音乐音效、字幕和色彩连续性。用户要求角色开口时，不能擅自全改为旁白，也不能用无声视频替代。若声音未生成或未试听，状态只能是 `VIDEO_DRAFT_NO_AUDIO`，不得写成成片。
7. **独立审片与返工**：制作方自检后，交独立审查方读取冻结标准和真实成片。按问题定位局部重做；修改后重新审对应版本。没有独立审片证据时状态为待审，不能签最终通过。
8. **交付与复盘**：导出成功且检查了实际文件或可播放结果后，提供成片、可编辑工程、字幕和简短审查结论。保留成本、模型、失败和改进记录。只有真实端到端成功后才升级能力证据等级。

### 声画最低验收

- 台词存在时，逐句核对说话人、文本、实际时长和落点；不允许漏句、串角色或用旁白偷换正面对白。
- 配音先试听代表句，再批量生成；声音被判定机械、情绪错位或难听时，先换音色、表演指令或分句方式，不把整段生成费用继续压在错误声音上。
- 最终至少做三遍检查：只听声音、静音看画面、声画合看。任一遍存在致命问题，交付状态退回草稿。
- 没有对白的镜头仍应检查必要的环境声、动作音效和配乐；只有用户明确要默片时才允许无声成片。

## 状态与恢复

每个项目维护 `production.json`，内容按制作规范记录，阶段依次为 `PLANNED → DIRECTION_PASS → ASSETS_READY → PILOT_PASS → GENERATING → EDITED → CANDIDATE_EXPORTED → REVIEW_PASS → DELIVERED`；需要人工时用 `WAITING_USER`，接口等待用 `WAITING_JOB`，能力缺失用 `BLOCKED_CAPABILITY`，附恢复阶段。导出状态和审核状态分别保存；已导出但音频未检仍是待审候选。最终交付必须审核同一版本。

重启先读状态、工程和已提交任务，不重复计费。异步任务按工具真实语义跟踪；当前宿主提供续接或自动化且用户授权持续执行时，使用官方续接机制。没有机制则保存 jobId、下一步和等待状态并如实说明，不承诺无人唤醒也会后台完成。

同一根因两次文字调整无效就更换参考、动作拆法或生成模式；三次失败后复核路线，预算允许时尝试实质不同方案。付费前估算完成余下全片的费用（包括声音、导出和返工预留），不能把预算都用在开头几镜。已花费、在途预留、剩余全片预估与返工预留之和超过上限时，先在硬标准内调整方案。任一关键费用未知且没有可靠扣费上限时，不提交新付费请求；确认费用或取得明确金额的追加授权后继续。任何阶段工具缺失都先完成不依赖它的工作，再报告具体缺口。

## 用户看到的内容

普通工作不把 JSON、提示词和参数交还用户填写。只在有用时简短汇报方向、小样结果、进度变化和完成情况。交付明确区分“规划完成”“动画草稿”“已导出待审”“独立审核通过”，并说明未完成项。Skill 安装通过结构校验不等于已经证明能自动拍好动画。
